# Arbor

## 开始使用

按 [Docker 快速开始](../README.md#docker-快速开始) 初始化管理员，再从「系统设置 → 成员」生成一次性邀请链接。成员可以使用本地账号。需要飞书登录或提醒时，按 [部署说明](DEPLOY.md) 配置飞书应用。

## 项目和任务

在「项目」里创建项目，再添加需求和任务。任务可拆成子任务，也可以直接挂在项目下。工作项可分别设置负责人、执行人和验证人，方便处理指派和验收。

- 在列表或时间线里查看计划。任务的进度按工作量向上汇总，子项阻塞会在上级显示。
- 有固定交付周期时，可以在项目内创建迭代，把需求和任务归入对应周期。
- 工作台汇总待验收、被打回、阻塞和临近到期的事项。从工作项详情的「下一步」查看当前要处理的动作。

## 提交和验收

执行人提交交付物链接，由验证人通过或填写原因打回。提交、评审、缺陷和返工记录都保留在工作项里。

- **需求验收**要有验收标准，未关闭的 P0/P1 缺陷会拦截验收。有子任务的需求会在下级完成后进入整体验收。
- **生产发布**是新建需求的默认流程。测试验收通过后，由执行人登记生产版本或发布链接，再由验证人确认线上结果。线上验收打回后，修复工作需要重新走测试验收和发布。
- **AI 应用**可以记录 Prompt 版本、评测通过率、调用成本和 Bad Case。需求的完成检查项可依据已记录的评测结果、成本预算和 Bad Case 处理状态判断是否达标。

## 团队与权限

在「系统设置 → 角色」中管理菜单权限和项目范围。系统提供管理员、成员和访客三个内置角色，也支持自定义角色。角色详情可添加或移除成员，编辑角色会同步更新已分配成员的权限。

在「系统设置 → 成员」管理账号启停、邀请和代码平台用户名。个人从工作台查看待办，项目负责人可在团队页面查看成员负载和动态。

## 代码仓库与飞书

- **代码仓库**支持 GitHub、GitLab、Gitee 和 Gitea。绑定仓库后，在分支名、PR / MR 标题或描述中写入 `AR-<任务编号>` 即可关联工作项。Arbor 按平台支持的事件同步评审、测试和合并结果。有业务验收或发布要求的工作在合并后仍按原流程处理。 [各平台配置](DEPLOY.md#代码仓库)
- **飞书**可用于登录和消息提醒。配置应用、接收人及项目群后，可发送交接和风险提醒。开启调度后可发送每日待办摘要和项目周报。应用内的个人周报可从工作台查看和复制。 [飞书配置](DEPLOY.md#飞书与代码仓库配置)

## 质量与绩效

质量中心汇总缺陷和验证记录。绩效看板使用有权限查看的工作项数据，展示近 90 天的交付、质量和验证贡献。交付按需求负责人归属，评审和验收贡献按记录中的验证人归属。缺少有效样本时显示「—」。
